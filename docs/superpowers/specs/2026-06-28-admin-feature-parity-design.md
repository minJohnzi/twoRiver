# TwoRiver 后台功能产品化对齐设计

- 日期：2026-06-28
- 状态：已确认，待实施计划
- 参考模板：`E:\个人技术博客后台管理系统`
- 交付方式：一次性整体替换

## 1. 目标

以 `E:\个人技术博客后台管理系统` 为功能与交互参考，将模板中的后台菜单和可用能力产品化到 TwoRiver。模板不作为独立应用或运行时依赖；TwoRiver 继续使用现有 React/Vite、Fastify、SQLite、session/CSRF 和上传体系。

最终版本必须端到端贯通：后台保存的页面、项目、导航、站点信息、SEO 和主题配置要真实影响公开站点；统计、账户、备份与维护操作必须由真实数据和真实系统行为支撑。

## 2. 已确认决策

1. 采用产品化对齐。模板中的模拟功能只在有真实业务含义时实现。
2. 所有新增站点内容端到端接入公开前台。
3. 独立页面、项目、导航、站点标题与简介、SEO 信息全部支持 `zh/en`，缺失时回退另一语言。
4. 访问统计采用隐私优先的站内方案，不保存原始 IP，不使用跨站 Cookie 或浏览器指纹。
5. 保持单管理员模型，增加资料、用户名和密码维护，不引入角色权限。
6. 备份同时支持完整下载和恢复。
7. 文章状态统一为 `draft / published / archived`；删除先进入保留 30 天的回收站。
8. 自定义页面使用 `/pages/:slug`；项目使用 `/projects` 与 `/projects/:slug`。
9. 主题配置真实影响公开站点，不改变后台控制台主题。
10. 采用一次性整体替换，不做阶段性上线。

## 3. 正式后台菜单

后台正式菜单必须包含：

1. 仪表盘
2. 文章管理
   - 文章列表
   - 新建文章
   - 草稿箱
3. 分类管理
4. 标签管理
5. 页面管理
6. 资源管理
7. 项目展示管理
8. 导航菜单管理
9. 站点设置
10. 数据统计
11. 系统设置

主题演示不进入正式后台。模板中的虚构 CDN 操作、匿名遥测和模拟恢复出厂功能不保留。

## 4. 总体架构

### 4.1 保留的工程边界

- `apps/web`：React/Vite，承载公开博客和后台控制台。
- `apps/api`：Fastify，承载公开 API、管理员 API、匿名统计和系统操作。
- `packages/shared`：维护 Zod 请求响应模型与共享 TypeScript 类型。
- SQLite：保存业务内容、站点配置、匿名统计、审计事件和资源登记信息。
- uploads：保存文章图片、头像、项目封面和资源文件。

### 4.2 后端模块

后端按职责拆分为：

- 发布与文章生命周期
- 分类与标签
- 独立页面
- 项目展示
- 资源与引用关系
- 导航与站点设置
- 匿名统计
- 管理员账户与会话
- 备份恢复与系统维护
- 审计事件与系统健康

模块通过明确的 repository/service/route 接口协作。公开 API 与管理员 API 分离；所有管理员写操作继续校验 session、CSRF、请求 schema 和速率限制。

### 4.3 模板边界

模板的 `localStorage`、mockData、模拟上传、模拟统计和演示按钮不得进入正式实现。完成替换后移除 `apps/web/src/admin-console` 模板副本，并确保构建产物不包含模板应用代码或素材。

## 5. 数据模型

### 5.1 文章

扩展现有文章模型：

- 状态：`draft / published / archived`
- `is_pinned`：列表置顶
- `is_featured`：首页精选
- `cover_url`：封面资源
- `deleted_at`：回收站时间
- `published_at`、`created_at`、`updated_at`：保留现有语义
- 中英翻译继续存放于文章翻译表

现有 `hidden` 数据在迁移时转换为 `archived`。回收站内容不出现在普通后台列表和公开 API；30 天后才允许永久删除。

### 5.2 分类与标签

分类增加排序值和中英描述，保留名称与 slug；文章数量由关联关系实时或汇总计算。标签保留名称与 slug，引用数量由文章关联计算。存在有效文章引用时，分类和标签不能直接删除。

### 5.3 独立页面

新增页面主表与翻译表：

- 主表：slug、状态、排序、创建/更新时间、删除时间
- 翻译表：locale、标题、Markdown 正文、SEO 标题、SEO 描述

状态使用 `draft / published`。未发布页面不出现在公开 API。

### 5.4 项目

新增项目主表与翻译表：

- 主表：slug、技术栈、封面 URL、GitHub URL、演示 URL、排序、公开状态、精选状态
- 翻译表：locale、名称、描述、SEO 标题、SEO 描述

### 5.5 导航与站点设置

导航项保存内部/外部 URL、排序、启用状态、新窗口标记；翻译表保存 `zh/en` 名称。

站点设置主表保存 Logo、favicon、robots 规则和主题参数；站点设置翻译表按 `zh/en` 保存站点名称、副标题、默认 SEO 标题、描述和关键词。社交链接使用独立有序表。作者头像、昵称和简介复用 About 数据，不维护第二份冲突资料。

### 5.6 资源

新增资源登记表，保存 URL、存储路径、原始文件名、MIME、大小、类型、文件夹、来源、创建时间和校验信息。资源引用从文章、页面、项目、About 和站点设置中计算或维护，后台展示引用次数和影响范围。

### 5.7 统计与审计

匿名访问明细保存路径、内容类型与 ID、语言、来源域名、设备类别、时间和每日访客哈希。原始 IP 不写入数据库。匿名明细保留 90 天，日级汇总长期保留。

审计事件保存管理员操作类型、目标、结果、时间和必要的非敏感上下文，用于系统日志、备份恢复记录和维护任务结果。

### 5.8 管理员

扩展现有用户表，支持用户名、显示名称、邮箱、头像、密码哈希和更新时间。系统保持单管理员业务约束。

## 6. 发布与内容管理

### 6.1 仪表盘

仪表盘展示真实的已发布、草稿、归档、分类、标签、资源、今日 PV 和累计 PV；包含近七日趋势、分类占比、最近编辑文章、快捷入口和系统健康摘要。

### 6.2 文章列表与草稿箱

文章列表支持：

- 搜索标题、摘要和 slug
- 按状态、分类和标签筛选
- 分页与空状态
- 内容预览与编辑入口
- 批量归档、批量移入回收站
- 从回收站恢复和永久删除
- 置顶、精选、封面、真实浏览量与更新时间展示

草稿箱作为独立入口，只展示 `draft` 内容，支持继续编辑、发布和移入回收站。

### 6.3 文章编辑器

保留现有能力：

- 中英双语内容
- Markdown 编辑、分屏、预览
- 正文搜索与大纲
- 图片选择、拖拽和粘贴上传
- 分类、标签、发布时间和 SEO
- AI 翻译及现有 AI 辅助

新增封面上传、置顶和精选。保存草稿、发布、归档和删除必须有明确反馈，不得因 API 失败丢失当前表单内容。

### 6.4 分类与标签

分类支持新增、编辑、排序、双语描述、文章数量和安全删除。标签支持搜索、标签云、引用数量、重命名、重复校验和安全删除。

### 6.5 资源管理

资源页支持全部/图片/附件过滤、文件名搜索、文件夹管理、上传、移动、预览、复制公开链接和删除。被引用资源删除前必须展示影响范围并要求先解除引用。

批量数据库操作在事务中执行。数据库与文件联合操作使用临时文件和补偿清理，避免产生半完成状态。

## 7. 站点内容与公开前台

### 7.1 独立页面

后台支持创建、编辑、发布、转草稿和删除双语 Markdown 页面。公开地址为 `/pages/:slug`；草稿和不存在的页面返回 404。`about`、`categories`、`tags`、`posts`、`projects` 和 `admin` 等保留字不能作为自定义内容 slug。

### 7.2 项目展示

后台管理双语名称与描述、slug、技术栈、封面、GitHub、演示地址、排序、公开状态和精选状态。公开站点提供 `/projects` 列表和 `/projects/:slug` 详情；精选项目可进入首页展示区域。

### 7.3 动态导航

导航支持双语名称、内部或外部 URL、排序、启用状态和新窗口打开。内部 URL 必须为合法站内路径；外部 URL 只允许 `http/https`。前台桌面和移动导航读取同一数据源，语言切换后立即使用对应名称。

### 7.4 站点设置与 SEO

站点设置管理双语站点名称、副标题、默认 SEO 标题/描述/关键词、Logo、favicon、社交链接、robots 规则和主题参数。公开站点通过统一配置接口加载这些数据，无需重新构建即可生效；API 根据已保存规则动态提供 `/robots.txt`。

路由变化时更新本地化页面标题、描述、canonical 和 robots 元信息。内容翻译缺失时回退另一语言，但 canonical 与当前实际 URL 保持一致。

### 7.5 主题

- 主色：通过受控 CSS token 影响链接、按钮和选中状态。
- 首页布局：列表、网格和 Bento。
- 代码高亮：四套受支持主题。
- 字号：小、中、大三档。
- 深色模式：默认跟随系统；站点可配置是否允许读者覆盖。

读者主题偏好只保存在本地，不写入匿名统计。主题设置不改变后台控制台样式。

## 8. 隐私统计

公开路由完成后发送一次访问事件。服务端记录路径、内容类型与 ID、语言、来源域名、设备类别和时间，并使用独立的 `ANALYTICS_HASH_SECRET` 与 UTC 日期派生每日密钥，再对 IP 与 User-Agent 生成匿名访客哈希。生产环境缺少该密钥时拒绝启动统计采集。原始 IP 不保存，不使用跨站 Cookie 或浏览器指纹。

后台提供：

- 7/30/90 天 PV 与 UV
- 来源渠道与设备分布
- 热门文章、热门页面和热门标签
- 趋势图与 CSV 导出

后台访问、已识别爬虫和重复短时上报不计入公开流量。统计上报失败不得影响公开页面访问。

## 9. 账户与系统运维

### 9.1 管理员账户

系统设置支持昵称、邮箱、头像和用户名更新。修改密码必须验证旧密码，使用 Argon2 重新哈希，并撤销除当前会话外的全部会话。敏感操作进入审计日志。

### 9.2 备份下载

后台生成包含以下内容的压缩包：

- 一致性 SQLite 快照
- 完整 uploads 目录
- 版本、时间、文件清单与校验值
- 恢复所需元数据

### 9.3 备份恢复

恢复前依次执行格式、版本、校验值和磁盘空间校验，再验证管理员密码并自动备份当前状态。恢复过程进入短暂维护状态：暂停全部后台写操作，公开请求返回明确的 503 维护响应。恢复使用临时目录和原子替换；任何步骤失败都保持当前站点不变并返回可读错误。

### 9.4 系统状态与维护

系统设置展示 API 运行时间、数据库状态与大小、上传目录可写性与容量、迁移版本、最后备份时间、回收站数量、孤立文件数量和统计任务状态。

维护工具只执行真实操作：清理过期会话、孤立上传、超过 90 天的统计明细，以及 `deleted_at` 已超过 30 天的回收站内容。到期回收站内容可由管理员永久删除，也可由明确显示执行范围的维护任务批量清理。系统日志展示真实审计事件、备份恢复记录和维护任务结果。

## 10. 错误处理

API 使用统一错误结构，区分校验失败、未认证、权限拒绝、资源冲突、文件错误和系统故障。后台表单失败时保留输入，提交期间禁止重复操作，列表错误提供重试入口。

备份恢复期间暂停后台写操作。数据库与文件系统操作必须具备事务、临时文件或补偿机制。任何非关键能力失败，例如统计上报或健康摘要，不得阻断公开内容读取。

## 11. 迁移与一次性替换

上线前自动备份现有 SQLite 与 uploads。迁移必须保留现有文章、翻译、分类、标签、About、资源和管理员账户，并执行：

- `hidden` 转换为 `archived`
- 新增字段写入安全默认值
- 现有上传文件登记到资源表
- 新增站点设置写入与当前公开站点一致的默认值
- 新增表与索引完成完整性校验

迁移必须先在现有数据副本上演练。迁移失败时 API 不启动新版本；上线后出现阻断问题时，使用上线前快照恢复数据库与 uploads，并回退应用版本。

## 12. 测试与验收

### 12.1 自动化测试

- Shared：schema、双语回退、状态与 slug 规则。
- API：迁移、CRUD、批量操作、回收站、资源引用、认证改密、统计去重、备份恢复与失败回滚。
- Web：后台菜单、表单校验、筛选分页、语言切换、主题配置和错误状态。
- E2E：登录、创建双语文章、上传资源、发布页面/项目、导航生效、主题切换、统计入库、改密、备份和恢复。

### 12.2 视觉 QA

在桌面和移动视口验证后台菜单、表格、编辑器、弹窗，以及公开站点三种首页布局。不得出现溢出、遮挡、空白画面、不可读文本或无响应控件。

### 12.3 上线门槛

正式切换前必须通过：

- 现有数据副本迁移演练
- 完整备份与恢复演练
- 全仓 typecheck
- 单元与集成测试
- E2E 测试
- 生产构建
- 关键页面与 API HTTP 检查
- 桌面与移动视觉 QA

正式代码不得残留 mockData、模拟 API、主题演示入口或无效按钮。所有后台菜单必须由真实数据与真实操作支撑。

## 13. 非目标

- 多管理员、角色和权限系统
- 评论、邮件营销、计费或会员系统
- 第三方访问统计平台
- 跨站追踪、浏览器指纹或原始 IP 存储
- CDN 控制、匿名遥测和主题演示
- 把模板作为独立应用部署

## 14. 完成定义

一次性整体替换仅在本规格中的后台菜单、公开站点贯通、数据迁移、统计、账户、备份恢复、系统状态、自动化测试和视觉验收全部通过后完成。任何仅有界面但没有真实数据链路的功能均不视为完成。
