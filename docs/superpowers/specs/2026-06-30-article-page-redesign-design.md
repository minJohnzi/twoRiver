# TwoRiver 文章显示页重构设计

日期：2026-06-30

状态：已批准，待实现计划

参考页面：[Generate Reports in HTML, Not Markdown](https://gokul.site/blog/html-not-markdown)

本地参考资料：`E:\ref\Generate Reports in HTML, Not Markdown – Gokulakrishnan Kalaikovan.html`

## 背景

当前公开文章页已经支持文章请求、语言回退、Markdown 渲染、代码复制、图片灯箱、表格包装和返回顶部，但阅读页面仍沿用全站大头部，正文与元信息的视觉节奏也没有形成明确的文章阅读骨架。

本次重构采用参考页的高忠实方向：让文章本身成为首屏主角，使用窄正文、低噪声元信息、桌面端粘性目录、近乎纯黑的深色氛围和克制的代码块表现。同时保留 TwoRiver 已有的深浅主题、中英文切换和 Markdown 增强能力。

## 目标

- 为 `/posts/:slug` 提供文章专属的紧凑导航，不再显示公开页面的全站品牌头部。
- 将正文控制在舒适的阅读宽度，并在桌面端提供由正文 `H2/H3` 自动生成的粘性目录：始终显示全部 `H2`，仅展开当前 `H2` 下的 `H3`。
- 目录随滚动高亮当前章节；移动端完全隐藏目录，正文独占阅读区域。
- Markdown 只解析一次，同一次解析同时产出安全 HTML 和结构化目录数据。
- 深色和浅色主题都可用，且主题切换入口保留在文章紧凑导航中。
- 中英文切换时，标题、摘要、正文、目录、日期格式和所有文章页界面文案同步切换。
- 保持代码复制、图片灯箱、表格包装、语法高亮和后台 Markdown 预览的现有行为。
- 改善语义结构、键盘可达性、减少动画偏好和移动端表现。

## 非目标

- 不修改文章 API、数据库结构、发布流程或翻译数据模型。
- 不为移动端新增折叠目录、抽屉目录或悬浮目录按钮。
- 不增加阅读进度条、分享按钮、相关文章、作者卡片或评论区。
- 不重新设计首页、分类页、标签页、关于页或后台编辑器。
- 不引入新的运行时依赖。

## 已批准的视觉方向

采用“高忠实参考”与“A1 文章专属紧凑导航”组合。

### 文章紧凑导航

文章路由顶部使用一条低高度、单底边的紧凑导航。左侧为返回文章列表；右侧依次提供 `writing`、`about`、主题切换和语言切换。导航不显示 TwoRiver Logo 或大品牌名称，避免品牌头部占据文章首屏。

紧凑导航继承当前主题：深色状态使用近乎纯黑背景和低对比边线，浅色状态使用现有浅色主题变量。主题与语言控件使用文字形式，不引入新的图标或装饰胶囊。

### 桌面布局

- 文章页面外层最大宽度约为 1040–1080px。
- 主阅读列最大宽度约为 620px。
- 目录列约为 180–220px，与正文保持 48–80px 间距。
- 文章内容区在紧凑导航下方保留约 64–80px 的首屏呼吸空间。
- 标题使用紧凑的大号无衬线字体，桌面端最大约 56px；移动端约 36–40px。
- 正文基础字号约 16–17px，行高约 1.7–1.8。
- 元信息使用小号、低对比、轻微字距的排版；日期、分类和标签保持可换行。
- 页面不使用外层卡片、浮层容器、渐变、发光或装饰徽章。

目录在桌面端位于正文右侧并保持粘性。目录标题为本地化的“本文目录”或“On this page”。全部 `H2` 始终可见，只有当前 `H2` 分组显示其 `H3`；当前标题使用较高对比文字，当前 `H2` 在阅读其子节时仍保持强调。目录限制在视口高度内，超出后内部滚动，并使用弱化的细滚动条与上下渐变遮罩。

### 移动布局

- 在小于 1024px 的视口隐藏目录列。
- 正文使用约 20–24px 的左右留白。
- 紧凑导航允许控制项保持较小间距，但不得横向溢出；必要时降低字号，不将导航变成多行大块。
- 标题、摘要、正文、代码块、表格和图片都必须适应 320px 最小视口。
- 移动端不显示目录占位，不改变正文顺序，也不隐藏文章内容。

### Markdown 内容样式

- 正文标题、段落、列表、引用、表格、图片和链接统一使用参考页式的克制排版。
- 代码块继续显示语言与复制操作，但文章页隐藏彩色窗口圆点，将头部收束为低对比的语言/复制工具条。
- 行内代码、代码块、引用和表格使用边线与轻微表面色区分，不使用突兀阴影。
- 图片继续支持点击灯箱；图片本身保持自然宽度和圆角克制。
- 返回顶部保留为正文末尾的低调文本操作。

## 组件与职责

### `Layout`

`Layout` 识别 `/posts/:slug` 为文章路由。文章路由渲染新的 `ArticleNav`，其他公开路由继续渲染现有 `site-header`。管理员路由和登录路由逻辑保持不变。

`Layout` 继续持有主题与语言状态，因此 `ArticleNav` 直接复用现有的 `onThemeChange`、`onLocaleChange` 和路由预取意图处理。

### `ArticleNav`

新组件只负责文章路由的紧凑导航：

- 返回文章列表；
- `writing` 与 `about` 入口；
- 深浅主题切换；
- 中英文切换；
- 本地化的可访问名称和键盘焦点样式。

组件不读取文章数据，也不负责目录或正文滚动。

### `PostPage`

`PostPage` 保留现有的数据请求、语言回退、加载和错误处理。成功状态组合以下区域：

1. 文章元信息、标题和摘要；
2. 已渲染的 Markdown 正文；
3. `ArticleTableOfContents`；
4. 返回顶部操作。

`PostPage` 为正文区域维护一个容器引用，目录只在该容器内查找与观察标题节点，避免影响页面其他标题。

### Markdown 渲染契约

新增一个可测试的单次渲染入口：

```ts
interface ArticleHeading {
  id: string;
  level: 1 | 2 | 3;
  text: string;
}

interface RenderedMarkdownDocument {
  html: string;
  headings: ArticleHeading[];
}
```

渲染函数接收 Markdown 和当前语言所需的增强文案，返回 `RenderedMarkdownDocument`。它负责：

- 调用 `marked` 和现有代码高亮器；
- 通过现有 DOMPurify 流程净化 HTML；
- 包装代码块、表格和可预览图片；
- 扫描净化后的正文 `H1/H2/H3`；
- 生成稳定、去重的标题 ID；
- 同步返回目录数据。

文章页先生成一个 `RenderedMarkdownDocument`，再把同一个对象分别交给 Markdown 显示组件和目录组件，因此正文与目录在同一次 React 渲染中更新，不出现新正文搭配旧目录的一帧闪动。

后台编辑器仍可向 `MarkdownPreview` 传入原始 Markdown。`MarkdownPreview` 内部使用同一个渲染函数，但不显示或上报目录。为避免文章页重复解析，`MarkdownPreview` 增加接收已渲染文档的受控入口；其 props 使用 TypeScript 联合类型保证“原始 Markdown”和“已渲染文档”二选一。

Markdown 显示根节点由嵌套的 `<article>` 改为普通 `<div class="markdown-body">`。页面保留唯一的外层 `<article>`。

### 标题 ID 规则

目录只扫描正文内的 `H1/H2/H3`，文章页面标题不进入目录。作者写入正文的标题级别原样保留，不自动降级或提升。

ID 生成规则：

1. 使用标题的纯文本内容，忽略内部标记；
2. 使用 Unicode NFKC 规范化并转为小写；
3. 保留所有语言的字母和数字；
4. 将标点与连续空白折叠为单个连字符；
5. 去除首尾连字符；
6. 空结果使用 `section-1`、`section-2`；
7. 重复结果追加 `-2`、`-3`。

该规则必须覆盖中文、英文、混合语言、重复标题、仅标点标题和包含行内代码的标题。

### `ArticleTableOfContents`

目录组件只消费 `ArticleHeading[]` 和正文容器引用，不再次解析 Markdown，也不修改正文 HTML。渲染前按顺序过滤并分组标题：`H1` 不进入右侧目录；每个 `H2` 开启一个分组，后续 `H3` 归入该分组，直到下一个 `H2`；首个 `H2` 之前的孤立 `H3` 不进入目录。

组件使用 `IntersectionObserver` 观察正文标题：

- 当前视口上部的章节成为激活项；
- 向下滚动进入下一章节时更新高亮；
- 向上滚动时恢复前一章节；
- 所有 `H2` 始终显示，仅当前标题所属 `H2` 的 `H3` 子项展开；
- 同一 `H2` 内切换 `H3` 时只更新高亮，不折叠或重建分组；
- 当前项设置 `aria-current="location"`；
- 点击目录使用原生 `#id` 锚点；
- 平滑滚动只在用户未请求减少动画时启用。

正文没有 `H1/H2/H3` 时不渲染目录导航，但桌面正文仍保持批准的阅读轴，不因目录消失而大幅横向跳动。

## 主题与语言

文章页继续使用 `.app-shell[data-theme]` 和现有颜色变量。深色主题保持参考页的近黑背景；浅色主题使用现有浅色变量，不把浅色页面强制改成米白或暖灰。

切换语言时，以下数据作为一组重新计算：

- 页面标题；
- 摘要；
- 日期格式；
- 分类和标签名称；
- Markdown HTML；
- 结构化目录；
- 所有文章页操作文案。

目录观察器在新正文节点上重新绑定，旧的激活 ID 立即失效。语言切换不强制滚回顶部；浏览器保留当前滚动位置，再由新正文的观察结果确定当前章节。若 URL 中旧语言的 hash 在新译文中不存在，则通过 history API 清除无效 hash，不新增历史记录。

文章页文案至少包含以下中英文对：

| English | 中文 |
| --- | --- |
| Back to posts | 返回文章 |
| On this page | 本文目录 |
| Back to top | 返回顶部 |
| Loading article… | 正在加载文章… |
| Article not found | 未找到文章 |
| Copy / Copied / Failed | 复制 / 已复制 / 复制失败 |
| Open image preview | 打开图片预览 |
| Close image preview | 关闭图片预览 |

主题切换标签继续表达目标主题，而不是当前主题，例如深色状态显示“light”或“浅色”。语言切换标签表达目标语言，例如中文状态显示 `EN`。

## 加载、错误与空状态

- 加载状态保留紧凑导航，并在正文起始轴显示本地化的低对比加载文案。
- 错误状态使用本地化的稳定提示，不直接向读者显示接口原始错误；保留返回文章列表入口。
- 文章缺少可用翻译时使用与“未找到文章”一致的公开错误状态。
- 文章没有摘要时直接省略摘要区域，不留下空占位。
- 文章没有目录标题时省略目录，不显示空的“本文目录”。

## 可访问性

- `ArticleNav`、目录和正文使用明确的导航与文章语义。
- 页面只保留一个外层 `<article>`；Markdown 内容使用普通容器。
- 目录当前项使用 `aria-current="location"`。
- 主题、语言、返回、复制、图片灯箱和返回顶部均可通过键盘操作。
- 保留并校准 `:focus-visible`，确保深浅主题都有足够对比。
- 图片灯箱继续支持 Escape 关闭，并保持滚动锁逻辑。
- 平滑滚动和页面进入动画遵循 `prefers-reduced-motion`。
- 目录在移动端通过响应式样式隐藏，但正文顺序和内容不改变。

## 验收标准

- 文章页首屏与批准的高忠实参考方向一致，不再显示全站品牌头部。
- 桌面正文约 620px，目录位于右侧并保持粘性。
- 目录由正文 `H2/H3` 自动分组，始终显示全部 `H2`，只展开当前 `H2` 的 `H3`，并随滚动高亮。
- 目录限制在视口高度内，长目录可内部滚动，滚动条与上下边缘使用低干扰视觉处理。
- 移动端不显示目录，320px 宽度下无横向溢出。
- Markdown 在文章页只解析一次，HTML 与目录来自同一个渲染结果。
- 中英文切换不会短暂显示旧语言目录，且所有文章页操作文案同步切换。
- 深色与浅色主题均可从文章紧凑导航切换。
- 后台 Markdown 预览、代码复制、图片灯箱和表格行为无回归。
- 测试、类型检查和构建全部通过。
