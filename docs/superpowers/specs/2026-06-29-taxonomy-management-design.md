# 分类与标签端到端优化设计

日期：2026-06-29
状态：已完成交互确认，等待书面规格审核

## 背景

TwoRiver 当前已经具备真实的分类、标签、文章关联、软删除和后台 CRUD API，但管理体验与业务规则仍有几处脱节：

- 分类和标签共用一个不断膨胀的页面组件，两类工作流没有清晰边界。
- 标签管理缺少参考系统中的标签云、搜索和常驻快速编辑体验。
- 文章编辑器使用逗号分隔自由输入，保存文章时会隐式创建标签，并可能覆盖既有标签的显示名称。
- 管理列表只展示未进入回收站的文章引用数，但删除检查仍会看到回收站引用，导致“显示为 0 却不能删除”。
- 被引用的分类或标签只能阻止删除，缺少安全、可选择的快捷解除关联能力。

参考项目 `E:\个人技术博客后台管理系统` 提供了分类表格、标签云、标签搜索和多选标签交互。本设计吸收这些交互模式，但继续以 TwoRiver 的 Fastify、SQLite、共享 Zod schema、认证和 CSRF 机制为基础，不接入参考项目的模拟数据或 `localStorage` 数据层。

## 目标

1. 将分类和标签管理重构为职责清晰、可独立测试的生产组件。
2. 让分类、标签和文章编辑器都以数据库中的既有记录为唯一事实来源。
3. 在文章编辑器提供“搜索多选 + 受控快速创建”标签工作流。
4. 同时展示正常内容与回收站内容的引用数，并以完整引用数决定能否删除。
5. 提供可搜索、可勾选、可批量提交的解除关联面板，不删除文章。
6. 保持当前路由、公开页面和既有后台视觉改版兼容。

## 非目标

- 不直接挂载参考项目的整套后台应用或 `localStorage` 状态。
- 不引入拼音转换；中文名称的 slug 由管理员填写。
- 不提供一键强制解除全部关联并删除。
- 不实现分类或标签合并、slug 历史别名或公开 URL 重定向。
- 不实现分类拖拽排序；继续使用显式数字排序。
- 不重新设计公开分类页和公开标签页。

## 方案选择

采用“生产逻辑原生重构”：保留现有 API、数据库和后台样式体系，把参考系统的交互精华改造成真实 API 驱动的独立模块。

未采用的方案：

- 直接移植参考页面：字符串 ID、模拟数据和 `localStorage` 与当前真实数据模型冲突较大。
- 继续扩充统一页面：初始改动较少，但会进一步耦合分类、标签、引用面板和编辑器状态。

## 前端架构

### 路由壳

`AdminTaxonomyPage` 保留现有入口和 `kind` 参数，但只负责选择对应模块：

- `/admin/categories` 渲染 `AdminCategoriesManager`。
- `/admin/tags` 渲染 `AdminTagsManager`。

路由路径、管理员鉴权和懒加载方式不变。

### 分类管理

`AdminCategoriesManager` 负责：

- 加载、排序和展示分类。
- 展示名称、slug、当前后台语言的描述、排序值和完整引用统计。
- 打开创建/编辑弹窗。
- 新建分类时将默认排序设置为当前最大 `sortOrder + 1`；空列表从 `1` 开始。
- 通过引用数或“解除关联”入口打开共用引用面板。
- 只有 `totalPostCount === 0` 时才提供可执行的删除操作。

分类描述继续保存 `zh` 与 `en` 两个翻译记录。当前语言为空时，列表可以回退显示另一语言描述；编辑表单始终分别编辑两种语言，避免回退文本被误保存到错误语言。

### 标签管理

`AdminTagsManager` 使用参考系统的双栏工作流：

- 左侧：标签云、搜索框和明细表格。
- 右侧：常驻的新建/编辑表单。
- 搜索同时匹配名称和 slug，比较不区分英文字母大小写。
- 点击标签云会把该标签名称写入搜索条件并聚焦对应结果。
- 表格展示名称、slug、正常引用、回收站引用和操作。
- 有引用时，删除入口不可执行并引导打开解除面板。

标签颜色只用于界面表现，不进入数据库模型。标签编辑基于数字 ID，因此更改名称或 slug 不改变文章关联。

### 文章标签选择器

新增 `AdminTagSelector`，替换文章编辑器中的逗号分隔输入框：

- 加载数据库中的完整标签列表。
- 已选项以可移除标签块显示。
- 输入文字可按名称或 slug 搜索。
- 点击结果切换选中状态。
- 搜索无匹配时提供明确的“创建并选中”入口。
- 快速创建表单包含名称和可编辑 slug。
- 名称包含英文或数字且能被现有规则规范化时，自动预填 slug；中文名称无法生成有效 slug 时，slug 字段保持空白并成为必填项。
- 快速创建成功后把服务端返回的标签加入可选列表并选中；只有随后保存文章时才建立文章关联。

编辑器内部保存选中的标签对象或稳定 ID；构建文章请求时映射为标签 slug，以兼容现有文章输入结构。编辑既有文章时根据 API 返回的标签 ID/slug 恢复选中状态。

分类选择器继续使用已有分类下拉框，只允许 `null` 或数据库中已存在的分类。

### 引用解除面板

`TaxonomyReferencesPanel` 由分类和标签共用，接收 taxonomy 类型与 ID：

- 按需加载引用文章，不把完整文章列表塞进分类或标签列表响应。
- 分为“正常文章”和“回收站文章”两组。
- 每项显示当前后台语言标题、slug、状态和是否在回收站；标题缺少当前语言时回退到另一语言。
- 支持标题和 slug 搜索、逐篇勾选以及“全选当前筛选结果”。
- 提交按钮显示即将解除的数量。
- 批量解除成功后保留面板上下文、清空已成功的选择，并刷新列表与外层引用统计。
- 不自动删除分类或标签；解除完全部引用后，管理员仍需明确执行删除。

面板关闭后把焦点还给触发按钮，支持 Escape 关闭，并使用合适的 dialog、label 和 live region 属性。

## 数据模型与共享契约

### 名称和 slug 唯一性

- `slug` 继续使用现有 `normalizeSlug` 规则并由既有数据库唯一约束保护。
- 分类名和标签名分别在去除首尾空格后执行不区分 ASCII 大小写的唯一约束。
- 新迁移创建表达式唯一索引：`lower(trim(name))`。
- API 在写入前主动检查名称和 slug 冲突，以便返回可读的 `409`；数据库索引负责抵御并发写入。

迁移在创建索引前查询历史冲突。若同一 taxonomy 中存在 `lower(trim(name))` 相同的多条记录，迁移抛出包含记录 ID、slug 和名称的明确错误，不自动合并、删除或改写公开 URL。管理员修正后可重跑迁移。

### 引用统计

管理端分类和标签对象增加：

- `activePostCount`：`deleted_at IS NULL` 的草稿、已发布和归档文章数量。
- `trashedPostCount`：`deleted_at IS NOT NULL`、仍存在于数据库且可恢复的文章数量。
- `totalPostCount`：以上两项之和。

已有 `postCount` 保留为未进回收站引用数的兼容字段，公开 API 和现有消费者无需立即迁移。新的管理界面只使用三个明确命名的字段；删除判断只使用 `totalPostCount`。

永久删除的文章记录和关联已经不存在，不计入任何引用统计。

### 引用文章摘要

共享 schema 增加 taxonomy 引用摘要，至少包含：

- `id`
- `slug`
- `status`
- `deletedAt`
- `titles`，键为可用的 `zh` / `en` locale

引用列表默认以未进回收站在前、更新时间倒序排列。前端负责当前语言标题回退。

### 批量解除输入

批量解除请求为 `{ postIds: number[] }`：

- 至少 1 个 ID。
- 最多 100 个 ID。
- ID 必须为正整数并在请求内去重。

响应返回实际解除数量和刷新后的引用统计。请求只处理当前 taxonomy 与所选文章之间确实存在的关联；不相关或已经解除的 ID 不报错，因此重复请求保持幂等。

## API 设计

保留现有 CRUD API，并扩展管理列表响应的引用统计。

新增接口：

- `GET /api/admin/categories/:id/references`
- `POST /api/admin/categories/:id/detach`
- `GET /api/admin/tags/:id/references`
- `POST /api/admin/tags/:id/detach`

所有接口沿用管理员 session 和现有 CSRF 策略；写接口必须通过 CSRF 校验。

引用接口返回 taxonomy 是否存在、文章摘要列表和三类引用统计。taxonomy 不存在返回 `404`。

解除接口在单个 SQLite 事务中执行：

- 分类：仅对 `category_id` 等于目标分类且文章 ID 在请求集合中的记录执行 `category_id = NULL`。
- 标签：仅删除目标标签与请求文章 ID 对应的 `post_tags` 记录。
- 正常文章和回收站文章使用相同规则。
- 文章内容、状态、发布时间和软删除时间均不改变。

删除分类或标签仍在服务端事务内重新计算完整引用数。任何引用存在时返回 `409`，避免列表加载后发生新关联造成竞态。

## 文章写入规则

文章仓库不再调用 `ensureCategory` 或 `ensureTags` 创建 taxonomy：

- `categorySlug` 为 `null` 时不设置分类。
- 非空 `categorySlug` 必须解析到现有分类，否则文章请求返回可读的 `400`。
- 每个 `tagSlug` 必须解析到现有标签；任一未知标签都使整个文章写入失败，不产生部分关联。
- 重复标签 slug 在验证阶段去重。
- 保存文章不会更改分类或标签的显示名称。

快速创建必须先调用标签创建 API。创建成功后，编辑器再把返回标签放入待保存选择中。这使“创建 taxonomy”和“关联文章”成为两个明确操作。

## 错误处理与状态更新

- 列表、表单和引用面板均等待 API 成功后再更新，不使用可能显示假成功的乐观写入。
- 请求失败时保留表单内容、搜索词和勾选结果。
- `400` 显示具体输入问题；客户端可以提前提示，但服务端验证为准。
- `404` 表示记录已被其他操作删除，提示后刷新列表。
- `409` 区分名称冲突、slug 冲突和仍有引用三类消息。
- 快速创建遇到冲突时刷新标签列表；若已存在项与输入匹配，界面聚焦该项供管理员选择，不自动假定它就是所需标签。
- 认证失效继续交给现有全局登录流程。
- 加载请求在组件卸载或路由切换时取消，避免过期响应覆盖新页面状态。

## 数据流

### 快速创建并关联标签

1. 编辑器加载分类和标签。
2. 管理员输入搜索词；无匹配时打开快速创建。
3. 管理员确认名称和 slug。
4. 标签创建 API 校验唯一性并返回真实标签。
5. 编辑器把返回标签加入待保存选择。
6. 管理员保存文章。
7. 文章 API 在事务内重新解析所有 taxonomy，并写入文章与关联。

### 解除引用并删除 taxonomy

1. 管理列表展示正常、回收站和总引用数。
2. 管理员从引用数或解除入口打开引用面板。
3. 面板按需加载文章摘要，管理员筛选并勾选。
4. 解除 API 在事务内只解除选中关系。
5. 页面刷新引用列表和外层计数。
6. `totalPostCount` 归零后，管理员明确执行删除。
7. 删除 API 再次检查引用并删除记录。

## 测试策略

实现遵循测试先行，覆盖以下层次。

### 共享 schema

- 三种引用计数字段的非负整数约束。
- 引用文章摘要与 locale 标题结构。
- 批量解除拒绝空数组、重复 ID、非正整数和超过 100 个 ID。
- 分类与标签写入的名称和 slug 规则。

### repository 与 API

- 创建和更新时拒绝重复 slug。
- 创建和更新时拒绝仅大小写或首尾空格不同的重复名称。
- 迁移在历史名称冲突存在时给出可操作错误，并在无冲突时成功创建唯一索引。
- 正常、草稿、归档和回收站文章分别产生正确引用统计。
- 引用接口同时返回正常与回收站文章。
- 分类批量解除只把选中文章的分类设为 `NULL`。
- 标签批量解除只删除选中文章与目标标签的连接行。
- 重复解除返回零新增变更并保持成功。
- 超过 100 项、缺少认证或无效 CSRF 被拒绝。
- 有任意正常或回收站引用时删除返回 `409`；全部解除后可以删除。
- 文章写入接受已有分类和标签，拒绝未知 taxonomy，且失败时不产生部分更新。
- 保存文章不再创建 taxonomy 或改写标签名称。

### React

- 分类按 `sortOrder` 和名称稳定排序，新分类默认值为最大值加一。
- 分类表单分别加载和提交中英文描述。
- 标签云、名称/slug 搜索和常驻编辑表单行为。
- 名称或 slug 冲突显示在对应表单上下文中。
- 标签选择器加载现有标签、切换选择和恢复已有文章选择。
- 快速创建自动预填可生成的 slug；中文名称要求手动 slug。
- 创建成功后标签自动选中；文章保存前不产生关联。
- 引用面板分组、搜索、逐项选择、全选筛选结果和批量提交。
- API 失败后保留表单和选择状态。

### 端到端

覆盖完整管理员流程：

1. 创建分类。
2. 在文章编辑器快速创建并选中标签。
3. 保存文章并验证分类、标签关联。
4. 将文章移入回收站并验证回收站引用数。
5. 从 taxonomy 管理页选择性解除关联。
6. 验证文章仍存在、taxonomy 引用归零。
7. 删除已无引用的分类或标签。

## 工作区保护

当前分支存在大量未提交的后台改版。实施时只对本功能所需文件做增量修改：

- 不重置、不回滚、不覆盖用户已有变更。
- 修改已脏文件前先检查局部 diff。
- 不把 `apps/web/src/admin-console` 中基于模拟数据的整套应用接入生产路由。
- 每轮测试后检查 `git diff`，确保没有格式化或构建工具造成的无关改写。

## 完成标准

- 管理员可以分别高效管理分类和标签。
- 文章编辑器只能关联真实存在的 taxonomy，并支持受控快速创建标签。
- taxonomy 列表准确区分正常与回收站引用。
- 任何引用存在时都无法直接删除 taxonomy。
- 管理员可以选择文章并批量解除关联，而文章本身不被删除或更改状态。
- 共享 schema、API、前端和端到端测试覆盖关键规则。
- 全量测试、类型检查和生产构建通过。
